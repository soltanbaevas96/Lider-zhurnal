**Владелец — не программист**, работает через браузер. Раньше правки вносились вручную через GitHub, теперь — через Claude Code. Общение на русском. Стиль: делать готовое решение целиком, диагностировать причину до правок, не спешить.

## Роли пользователей (enum user_role)

- `admin` — завуч. Полный доступ + вкладка «Управление» (редактирование справочников).
- `director` — директор. Видит всё, но БЕЗ «Управления» (только просмотр).
- `teacher` — преподаватель. Свои занятия + журнал.
- `assistant` — ассистент. Помогает на занятиях, выбирается при создании урока. Есть зарплата (уроки × своя ставка).
- `office_manager` — офис-менеджер. Только СВОЙ офис: ученики, группы, оплаты.
- `senior_office_manager` — старший офис-менеджер. Все офисы (контроль).
- **куратор** — особый случай: роль `teacher`, НО есть карточка в таблице `curators`. Определяется в auth.jsx (флаг isCurator). Ведёт ИНДИВИДУАЛЬНЫЕ занятия с отдельными учениками (не группами), выбирает любых учеников центра, посещаемость не отмечает. Зарплата = уроки × ставка.

Флаги в auth.jsx: isAdmin, isDirector, isManager (admin||director), isOfficeManager, isSeniorOM, isCurator, managerOffice.

## Ключевые бизнес-правила

- **Занятие = 1/2/3 урока** (не часы). 1ч20м = 2 урока, 2ч = 3 урока. Считаем уроки, не часы.
- **Зарплата преподавателя/куратора/ассистента** = сумма уроков × его ставка.
- **Вместимость группы = 13** (по умолчанию).
- **Удаление = мягкое** (архивируем карточку, вход отключаем, история уроков сохраняется). Всегда с подтверждением.
- **Уникальность группы:** код уникален среди активных групп ОДНОГО офиса (не глобально).
- **Оплаты:** история (дата+сумма на каждую), офис-менеджер видит свой офис, долг не считаем.
- **Официальное англ. название центра:** "Pavlodar Oil Chemistry Refinery LLP" — НЕ относится к этому проекту, это для другой работы владельца. Здесь просто «Лидер+» / "Lider Plus".

## Важные технические уроки (грабли, на которые уже наступали)

1. **Supabase отдаёт максимум 1000 строк по умолчанию.** Для больших выборок (связи ученик-группа = 1197) ставь `.limit(100000)`. Иначе данные молча обрезаются.

2. **Два справочника:** `fetchDictionaries` (для Сводки/Табеля) и `fetchAllDictionaries` (для Управления). При добавлении сущности — добавляй в ОБА, иначе появится в одних вкладках и пропадёт в других.

3. **RLS-политики:** используй `auth.uid() is not null` для чтения, НЕ `auth.role() = 'authenticated'` (последнее не всегда срабатывает — кураторы из-за этого не читались).

4. **Логины сотрудников:** email вида `логин@lider-plus.kz`. Для рабочей учётки нужны: запись в auth.users с ПУСТЫМИ строками ('') в token-полях (confirmation_token и др., иначе GoTrue падает с 500), запись в auth.identities, профиль в profiles. Пароли хранятся зашифрованными (bcrypt) — расшифровать назад нельзя, поэтому «видимый» пароль дублируется в таблице `_issued_logins`.

5. **Дубли-призраки:** при импортах появлялись записи учеников/групп с пустым office. Они невидимы в фильтрах, но занимают уникальные коды и множатся в списках. Чистить: удалять записи с пустым office+договор, у которых есть полноценный двойник.

6. **Занятия куратора:** lessons.teacher_id и group_id сделаны nullable. Занятие куратора: curator_id заполнен, is_extra=true, group_id=NULL. Ученики — через таблицу lesson_students.
